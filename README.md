## 17.05.2026
На текущий момент проект представляет собой законченный NRT-конвейер для обработки платёжных транзакций с функцией обнаружения мошенничества. Включает:

- **Анализ и сравнение двух датасетов** (синтетический и реальный).
- **Обучение и сравнение 9 моделей ML** с применением SMOTE и взвешивания классов.
- **REST API** на FastAPI для приёма транзакций и получения предсказаний.
- **Хранилище истории** на SQLite.
- **Веб-интерфейс** на Streamlit для ручной проверки, статистики и мониторинга.
- **Генератор потока транзакций** для имитации NRT-нагрузки.

## Данные

### 1. Синтетический датасет (отработка методологии)
- **Источник:** [Financial Transactions Dataset for Analysis](https://www.kaggle.com/datasets/mdhossanr/financial-transactions-dataset-for-analysis) (Kaggle)
- **Размер:** 37 417 транзакций
- **Целевая переменная:** создана искусственно (z-score > 2.5 или интервал < 300 сек), доля аномалий увеличена до 2%.

### 2. Реальный датасет (апробация)
- **Источник:** [Online Payments Fraud Detection](https://www.kaggle.com/datasets/rupakroy/online-payments-fraud-detection-dataset) (Kaggle)
- **Размер:** 6 362 620 транзакций
- **Доля мошенничества:** 0.13% (естественный сильный дисбаланс)
- **Целевая переменная:** `isFraud` (готовая метка)

**EDA и feature engineering:**  
- Пропуски и дубликаты отсутствуют.
- Для синтетического датасета создано 13 признаков (временные, статистические, агрегированные).
- Для реального датасета использованы 7 признаков: `amount`, `oldbalanceOrg`, `newbalanceOrig`, `oldbalanceDest`, `newbalanceDest`, `step`, `type_encoded`.

## Моделирование

### Базовые модели (синтетический датасет)

| Модель | Precision | Recall | F1 | ROC-AUC |
|--------|-----------|--------|----|---------|
| Baseline RF (class_weight='balanced') | 0.066 | 0.647 | 0.120 | 0.783 |
| Balanced Random Forest | 0.064 | 0.700 | 0.118 | 0.779 |

*Высокая полнота, но 93–94% ложных срабатываний.*

### Улучшенные модели с SMOTE (синтетический датасет)

| Модель | Precision | Recall | F1 | ROC-AUC |
|--------|-----------|--------|----|---------|
| **Random Forest + SMOTE** | **1.000** | 0.327 | **0.492** | 0.785 |
| Gradient Boosting (без SMOTE) | 0.628 | 0.327 | 0.430 | 0.783 |
| XGBoost + SMOTE | 0.977 | 0.280 | 0.435 | 0.731 |

- **Вывод:** SMOTE резко повышает точность (до 100%) ценой снижения полноты.  
- **Улучшение F1 относительно базовой линии: +310%.**

### Эксперименты на реальном датасете

| Модель | F1 | PR-AUC | Precision | Recall | Переобучение (ΔF1) |
|--------|----|--------|-----------|--------|---------------------|
| **Random Forest (без SMOTE)** | **0.855** | 0.910 | **0.973** | 0.763 | 0.027 (незначит.) |
| Random Forest + SMOTE | 0.781 | 0.927 | 0.681 | 0.915 | 0.219 |
| XGBoost + SMOTE | 0.696 | 0.960 | 0.539 | 0.982 | 0.299 |
| LightGBM | 0.502 | 0.954 | 0.337 | 0.982 | 0.006 |

**Вывод:** на реальных данных Random Forest без SMOTE даёт лучший баланс (F1=0.855, Precision=97.3%, Recall=76.3%) и не переобучается. Модели с SMOTE сильно переобучаются из‑за сверхсильного дисбаланса.

## Сервис (API + UI + генератор)

### Компоненты
- **FastAPI** – эндпоинты:
  - `POST /predict` – предсказание одной транзакции
  - `GET /stats/{account_id}` – статистика по счёту
- **SQLite** – хранение истории всех транзакций и предсказаний
- **Streamlit UI** – ручной ввод, статистика, симуляция потока
- **Генератор транзакций** – имитация непрерывного NRT-потока (задержка 2 сек)

### Архитектура
Генератор / Клиент → FastAPI (/predict) → Random Forest → SQLite ← Streamlit UI
↓
Ответ (аномалия/вероятность)

### Запуск

1. **Установить зависимости:** pip install -r requirements.txt
2. **Запустить API:** uvicorn src.api.endpoints.main:app --reload (документация: http://127.0.0.1:8000/docs)
3. **Запустить UI (в другом терминале):** streamlit run frontend/app.py
4. **(Опционально) Запустить генератор потока:** python generator.py

### Тестирование производительности
- Пропускная способность: до 800 запросов/сек
- Средняя задержка: < 50 мс
- Сохранение истории: все транзакции записываются в SQLite

## Результаты
- Лучшая модель для production Random Forest (без SMOTE) на реальном датасете: F1=0.855, Precision=0.973, Recall=0.763.
- Разработанный конвейер готов к промышленной эксплуатации (API, UI, генератор, хранилище).
- Применение SMOTE на реальных данных привело к переобучению – важное наблюдение для будущих исследований.
